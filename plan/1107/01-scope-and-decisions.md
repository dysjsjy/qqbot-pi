## 2. 用户场景

- 群成员日常讨论：已启用采集的群中，可获取的文本持续保存；无需每条 @ 机器人。
- 群成员 `@bot /help` 或直接发送 `/help`：得到命令说明，不调用模型。
- 群成员 `@bot 问题` 或 `/memory 问题`：Java 检索本群历史，再由 pi 回答并列出来源。
- 同一成员 `/new`：重置自己的临时对话，保留群共享记忆；`/cancel` 只取消自己的即时问答。
- 管理员每天收到昨日群聊摘要，也可用 `/summary yesterday` 手动触发同一份日报。
- 管理员在 React 页面启停群采集、查询记忆、设置日报时间、查看失败原因和已生成报告。

直接以 `/` 开头的命令必须整条符合语法；正文中出现命令字样或引用文本不执行命令。普通问题只有明确 @ 本机器人时才自动回答。

## 3. 必做范围与规模

| 能力 | 首版边界 |
| --- | --- |
| 渠道 | QQ / 微信各一种已验证接入；至少各 1 个测试群，部署最多 5 个授权群 |
| 数据 | 接入并启用后的文本消息；不承诺补齐接入之前或网关不提供的历史 |
| 群规模基线 | 每群每天最多 1,000 条文本，且全文合计不超过 100,000 Unicode 字符；超量明确提示 |
| 会话 | 按“平台 + 账号 + 群 + 用户”隔离临时对话，群内共享 RAG 记忆 |
| RAG | 单一 embedding 模型、pgvector 精确检索、Top-K 引用；不做复杂记忆画像 |
| 定时任务 | 一种 DAILY_SUMMARY；每群一条配置；固定 Asia/Shanghai，每日 HH:mm，默认 09:00 |
| 管理员 | 一个网页管理员；群命令管理员按平台稳定 userId 白名单配置 |
| 部署 | 单 Java 进程、一个 PostgreSQL+pgvector、最多 2 个 pi 子进程；选定网关为外部依赖 |

“昨日一整天”指时间窗中的**全部已采集有效文本**，而非语义检索得到的若干段。断线、未开启采集、非文本以及数量超限须显示覆盖说明；未确认完整时不能称为“完整群聊日报”。

## 4. 明确后置

- 私聊、QQ 频道、微信公众号 / 客服入口、多协议同时兼容。
- 图片/语音理解、文件导入知识库、跨群检索、跨平台用户绑定。
- 多模型路由、重排模型、知识图谱、多层记忆、Agent 自主工具和 MCP。
- 任意 cron、自然语言创建任务、工作流编排、任务依赖 DAG、分布式调度。
- 多管理员、组织/租户、复杂 RBAC、SSO、前端低代码配置台。
- 微服务、Redis/MQ、独立向量库、Kubernetes、高可用、大规模压测平台。

这些项目不作为本 MVP 的依赖，不因未来可能需要而提前搭框架。

## 5. 必须先验证的接入能力

原服务号方案不能满足微信群采集；只有 @ 事件也不能支撑全天分析。M0 对每个平台验证：

1. 能获取测试群**未 @** 的普通文本及稳定的群 ID、用户 ID、消息 ID / 去重字段。
2. 能识别 @ 和消息类型，并把命令 / 问答发回原群。
3. 没有最近用户消息、不能借用旧被动回复凭据时，仍可主动发送定时报告。
4. 能观察登录/连接状态；是否重放、拉历史、补断线消息有明确结论。

QQ 先检验官方全群事件和主动发送权限，不具备时评估一个 NapCat / OneBot 11 网关；MVP 最终只实现其中一种。微信选择一个现成群聊网关，不自研登录协议；具体产品仍是前置未决项，不能用服务号替代验收。
