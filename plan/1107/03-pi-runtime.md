# 03 MVP pi 内核集成与进程生命周期

## 1. 复用边界

pi 负责 Agent 循环、模型适配、即时对话上下文及文本生成；Java 负责群采集、RAG 检索、日报分批编排、身份、队列、期限和发送。embedding 可由 Java 直接调用向量接口，所有问答和摘要生成均经过真实 pi。

即时问答按“群 + 用户”恢复临时上下文；RAG 来源由 Java 按本群权限检索后加入当前请求。日报每个分块和合并步骤使用独立短期上下文，不加载群成员的个人对话，也不把各分块无限累积到同一个会话中。两个运行槽位中最多一个执行后台摘要。

当前查阅上游源码版本字段为 `1.5.0`，对应文档基线提交为 `085c84e98e7f4c950f2be606466fff4f75d8fe7c`。这只能证明所查源码的状态，**尚未验证该版本 npm 发布包与文档完全一致**。M0 必须安装可用发布包、固定 lockfile、保存 `pi --version` / `pi --help` 与协议样本，再决定实施版本。

默认使用官方 CLI RPC，不额外引入 TypeScript HTTP 服务。若未来需要动态 Java 工具回调，可增加受控 pi 扩展或 SDK Worker；这是后续独立设计项。

## 2. 启动与隔离

以 `ProcessBuilder` 参数数组启动固定 Node 可执行文件和锁定包的 CLI 文件，禁止经 shell 拼接用户输入。每个子进程使用专用工作目录、受限环境变量和单独会话目录。

首版要求对应版本支持并验证以下行为：

```text
--mode rpc
--no-tools
--no-extensions
--no-mcp
--no-skills
--no-prompt-templates
--no-context-files
--no-approve
--system-prompt <由部署提供的固定提示词文件>
--provider <固定 provider>
--model <精确 model ID>
--session-dir <服务端生成的会话目录>
```

以上标志以锁定版本的 `--help` 为准；不支持时应使用等价、经过测试的隔离设置。不能静默忽略安全配置。即时对话使用持久会话；独立日报步骤允许使用 `--no-session`，其输入范围和生成结果持久化在 Java 业务表中。

使用独立的 pi 用户配置目录，避免读取开发者的个人凭据、全局扩展及项目提示词。具体配置目录环境变量在 M0 核实。工作目录不挂载项目源码、宿主机用户目录或平台密钥。

Java 拥有平台凭据；pi 子进程只收到所需模型凭据。模型密钥通过受控环境或凭据文件传入，不写在 CLI 参数、日志或请求正文中。

## 3. JSONL 协议约定

真实命令示例：

```json
{"id":"run-0001","type":"prompt","message":"你好，请介绍一下你能做什么。"}
{"id":"state-0001","type":"get_state"}
{"id":"cancel-0001","type":"abort"}
```

- 命令与 `response` 通过 `id` 关联；不能按返回先后顺序匹配。
- 普通会话事件通常没有命令 ID；通过“一个进程一次只运行一个业务任务”的绑定关系关联。
- 采用 UTF-8 字节流，按 LF 拆帧，兼容 CRLF，正确处理分片读取和中文多字节字符。
- JSON 字符串中的换行转义、U+2028/U+2029 不应生成额外帧。
- stdout 只解析协议，stderr 单独持续读取、限量保存并脱敏。
- 每帧大小设可配置上限，初始 8 MiB；超过时终止该运行并记录 `PROTOCOL_FRAME_TOO_LARGE`，不能无限扩容内存。
- 未识别的非关键事件跳过并计数；畸形 JSON、缺失关键字段或不兼容的完成语义使运行失败。

## 4. 一次运行的完成判定

1. 先安装事件消费者，再发送 `prompt`。
2. 收到 `response.success=true` 仅表示命令被接受，不表示模型完成。
3. 若 `disposition=handled`，按“未启动常规运行”处理；在本方案禁用扩展的配置下通常不应出现，记录异常，不无限等待。
4. 默认不使用 pi 内部 `steer/followUp` 队列；业务排队完全由 Java 管理。意外出现 `queued` 时检查进程归属，禁止误配结果。
5. 消费 `message_update` 可用于指标或缓冲，但不把思考内容、工具参数、stderr 发送给用户。
6. 以本次运行的 assistant `message_end` 为最终消息依据，检查角色、内容类型、停止原因和错误；不要直接取上一次会话的“最后回复”。
7. 查阅版本使用 `agent_settled` 作为整个运行停止的信号。`agent_end` 后可能仍有自动重试或压缩，不能立即发送最终答案。
8. 运行已结束也可能是中止/错误；只有具有有效最终文本、终止原因正常且 generation 未过期，才进入结果持久化。

如果最终固定的旧版没有 `agent_settled`，必须单独实现并验证该版本的空闲判定适配器。首版优先选择与上述协议兼容的发布版本。

## 5. 状态与超时

```text
STOPPED -> STARTING -> IDLE -> RUNNING -> IDLE
                          \-> CANCELLING -> IDLE / BROKEN
STARTING / RUNNING / IDLE -> BROKEN -> STOPPED
```

| 项目 | 首版默认值 | 到期行为 |
| --- | --- | --- |
| pi 启动及 get_state 健康探测 | 15 秒 | 失败退出，任务保持明确失败/待调度状态 |
| RPC 普通命令响应 | 5 秒 | 记录协议超时，检查进程健康 |
| 即时问答 / 单个日报生成步骤 | 60 秒 | 取消，不继续发送迟到的结果 |
| 即时任务期限 | 入站后 120 秒，且不超过平台回复截止时间减安全余量 | 包含排队与生成；过期任务不再调用模型 |
| 日报整体期限 | 领取运行后 30 分钟，最多 40 次生成调用 | 覆盖所有分批、合并步骤；超限标记失败/不完整，不冒充完整日报 |
| 取消宽限 | 3 秒 | 仍未空闲则强制结束该进程树 |
| 空闲进程保留 | 最多 120 秒 | 容量不足时优先回收空闲进程；日报独立步骤完成即释放，不占用即时问答槽位 |

总体期限由 Java 负责。pi 自动重试必须配置为有界，且计入同一生成期限；Java 不再叠加一套无上限的模型重试。日报等待槽位及暂停策略见 [12](12-scheduled-jobs.md)，不能用即时问答的 120 秒期限限制整份日报。

`/cancel` 定位当前会话运行；先禁止该任务创建/发送新的 Outbox，再按锁定版本处理 `clear_queue` 与 `abort`。检查 `abort` 回应和空闲状态，不能只发送命令就释放进程。已被平台接受的消息无法靠取消收回，验收以取消生效时尚未发送的结果为边界。

## 6. 上下文与崩溃恢复

- Java 保存业务会话 ID、generation、pi session ID、工作文件路径、最后已提交检查点引用；MVP 每个会话只保留一个有效恢复点，不做检查点版本管理界面。
- 一条业务会话只有一个文件写入者；首版禁止多个 Java 实例同时挂载并处理同一会话卷。
- pi 原生会话格式是模型上下文的依据；Java 消息表用于审计、任务与发送状态，不自行拼接一个不同版本的上下文。
- 一次运行正常结束后，确认 pi 已空闲且文件完整，把原生会话文件复制为不可变检查点，原子落盘并记录摘要；再在数据库事务中提交结果、检查点指针和 Outbox。
- 文件与数据库没有跨介质事务。先落盘后提交数据库：数据库失败留下的孤立检查点可清理；只有数据库已引用的检查点视为有效。
- 进程恢复时复制最后已提交检查点到新的工作文件，再用 pi 支持的会话恢复方式打开。M1 必须实测复制后会话 ID、分支和工作目录行为。
- 崩溃时处于 RUNNING 的任务标为 `INTERRUPTED`，不自动再次生成；恢复最近已提交上下文。未提交的这一次生成可能丢失，允许用户重发。
- 已提交结果但尚未发送的任务直接恢复 Outbox，禁止再次请求模型。
- 如果没有检查点，新建空会话；检查点损坏时隔离该会话并明确提示重置，禁止加载其他用户的文件。
- `/new` 提升 generation，取消自己的旧任务和排队消息，建立空会话。旧 generation 的迟到事件、结果和未发送 Outbox 不得进入新会话；群 RAG 记忆仍然存在，再次检索可重新命中群历史。
- 群记忆清除提升 memoryEpoch，旧 epoch 的检索结果和未发送日报必须废弃，并关闭该群现有 pi 会话，避免已注入历史继续留在上下文中。

不承诺“模型生成恰好一次”。目标是已完成上下文可恢复、未知运行不盲目重放、结果不会错发给其他用户。

## 7. MVP 验收

- AC-PI-01：真实 pi 请求、中文拆帧、正确的最终完成判定；问答和日报都走真实内核。
- AC-PI-02：取消、超时、禁用工具与输出过滤；用户消息不能加载资源或操作进程。
- AC-PI-03：临时会话隔离、最后有效检查点恢复、未完成任务中断；日报使用独立上下文。

仅支持 M0 固定的一套 RPC 协议；多版本兼容矩阵、动态扩展和通用工具回调均后置。
