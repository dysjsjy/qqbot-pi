# 04 群消息、命令、会话和存储

## 1. 统一消息与采集分流

`InboundGroupMessage` 最少包含：`channel`、`botAccountId`、`groupId`、`senderId`、`messageId/dedupeKey`、`occurredAt`、`receivedAt`、`segments`、`mentionsBot`、`isSelf`、`traceId`。ID 以字符串保存；时间存 UTC，报表按 Asia/Shanghai 计算。

1. 验证平台签名或网关认证，确定账号和群；只有网页启用的群才采集。
2. 用平台/账号/群/稳定消息标识去重；缺少可靠标识时 M0 必须验证稳定组合键，不能按单纯文本哈希去重。
3. 将有效原文事务写入 `group_message`，保留发送者与时间。重复投递不重复写库/索引/执行命令。
4. 普通非 @ 文本进入 RAG 待索引状态，不自动创建问答任务；日报直接读原文。
5. 严格命令优先由 Java 处理；@ 自然语言问题创建即时任务。队列满时保留消息，问答回复繁忙状态。
6. 按接入协议在提交后确认。若网关没有确认/重放能力，记录这一限制和断线缺口，不承诺无损接收。

机器人自身消息、回声和系统通知不进入 RAG/日报输入，避免把生成内容当作新事实循环总结。非文本仅记录类型/数量；仅被 @ 询问不支持类型时给能力提示，普通图片消息不刷屏。

## 2. 两种记忆的作用域

| 数据 | 隔离键 | 用途 |
| --- | --- | --- |
| 临时 pi 对话 | 平台 + 账号 + 群 + 发言者 | 多轮追问，`/new` 只清这里 |
| 持久群记忆 | 平台 + 账号 + 群 | 群成员共同讨论的历史，RAG 检索 |
| 日报运行 | 平台 + 账号 + 群 + 业务日期 | 汇总该日采集全文，独立临时 pi 上下文 |

同群成员可以检索本群已采集消息，这是明确的产品行为；不同群、账号、平台不共享数据。个人临时对话不能直接注入其他用户会话。公开发送到群的问题本身属于群消息，仍可能成为本群 RAG 的来源。

`generation` 用于废弃已重置对话的旧结果；`memoryEpoch` 用于群记忆清除后废弃旧索引、RAG 和日报结果。二者不能混用。

## 3. 首版命令表

支持 `@bot /命令` 与整条消息以 `/命令` 开头；`@bot 普通问题` 发起问答。未识别命令只返回 help 提示，不转发为 pi 控制命令。

| 命令 | 谁可用 | 行为 |
| --- | --- | --- |
| `/help` | 授权群成员 | 列出功能、示例和限制；管理员额外看到日报命令 |
| `/new` | 授权群成员 | 取消自己的当前问答与排队项，重置自己的临时上下文；明确提示群记忆仍保留 |
| `/cancel` | 授权群成员 | 取消自己的当前问答；不停止别人的问答或群日报 |
| `/memory <问题>` | 授权群成员 | 检索本群持久记忆，经 pi 回答并引用来源；无结果明确说明 |
| `/summary yesterday` | 配置的群管理员 | 创建/返回本群昨日同一日报；与 09:00 自动任务共用幂等键 |

MVP 不提供任意日期参数、命令配置器、群内改密钥或聊天形式的 cron 创建。群管理员身份用平台稳定 userId 白名单判断；昵称、群成员发送的“我是管理员”文字不具有权限。

## 4. 最小数据库结构

| 表 | 核心内容 / 唯一约束 |
| --- | --- |
| `group_config` | GroupScope 唯一；启用采集/回复、管理员 ID、接入时间、memoryEpoch |
| `group_message` | scope + message_key 唯一；文本、发送者、时间、类型、索引状态、删除标记 |
| `conversation` | scope + sender_id 唯一；generation、pi session、最后有效检查点 |
| `agent_run` | 入站来源、作用域、任务类型、状态、最终文本、期限；一次即时请求一个运行 |
| `memory_chunk` | scope、来源消息 ID、原文片段、embedding/version、epoch、时间范围 |
| `daily_schedule` | group_id + task_type 唯一；enabled、local_time、zone、next_run_at、revision |
| `daily_run` | group_id + task_type + business_date 唯一；触发方式、状态、coverage、报告、attempt |
| `outbox` | 业务结果键 + part_index 唯一；目标群、发送状态、attempt、epoch、平台回执 |
| `collection_gap` | scope、开始/结束、原因；连接/采集不完整的已知区间 |
| `admin_audit` | 管理操作、目标和结果；不含正文/密钥 |

以上表及任务幂等键中的 `group_id` 指内部 `group_config.id`，其唯一对应完整 GroupScope，不是可能跨平台重复的裸群号。来源引用可存消息 ID 数组/JSONB；首版不建设通用文档资产表、事件总线或复杂审批表。逻辑表可依据实现合理合并，但唯一约束和数据作用域不可省略。

## 5. 可靠性最小要求

- 即时任务：`QUEUED → RUNNING → SUCCEEDED / FAILED / CANCELLED / INTERRUPTED`；只对明确未开始的 QUEUED 自动恢复。
- 生成结果与 Outbox 在一个数据库事务提交。已生成结果重启后只恢复发送，不重新请求模型。
- 发送：`PENDING → SENDING → SENT / FAILED / UNKNOWN`。只有明确未接受且可重试的错误才有限重试，最多 3 次；网络结果未知默认不自动重发。
- 官方 QQ 若使用来源序列，重试同一段复用 msg_id/msg_seq；网关 API 不假定具有相同幂等能力。
- 普通回复 / 日报都分段不超过平台长度，最多 3 段；完整日报保存在管理员页面，群内超长部分明确截断。
- 发送前重新检查群启用状态、generation/epoch 和目标，不由模型决定目的群。
- 日报是独立的主动消息，不拿昨天的被动回复凭据发送，也不绕过平台权限。

## 6. 采集范围与数据缺口

按消息发生时间归属自然日，记录接收时间识别迟到。开启采集、登录失效、断线、服务停机、网关无法重放都形成已知覆盖区间或缺口；启动时不能因为连接恢复就把过去缺口自动标为已补齐。

MVP 不要求历史拉取。若选定网关能可靠补齐，可用消息 ID 去重后填补区间；否则日报标为“已采集记录摘要”。迟到消息会进入 RAG，但不会自动重发已经生成的旧日报。

## 7. 验收

AC-GRP-01 验证全群采集及去重；AC-GRP-02 验证命令权限、作用域与不刷屏；AC-GRP-03 验证跨群隔离、重启与未知发送。RAG 和日报分别按 [11](11-rag-memory.md)、[12](12-scheduled-jobs.md)执行，不能用临时 pi 历史代替持久记忆。
