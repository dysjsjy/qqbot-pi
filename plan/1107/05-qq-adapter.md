# 05 QQ 群接入 MVP

## 1. 接入必须支持的能力

QQ 群是第一条开发验证链路。需要接收普通群文本（包括未 @ 消息）、识别群/用户/消息 ID 和 @、回复命令，并能在没有新消息触发时主动发日报。仅有 `GROUP_AT_MESSAGE_CREATE` 不够。

本期不要求单聊、频道、附件下载或群成员管理；不做两套 QQ 协议长期兼容。

## 2. M0 选一种路线

| 路线 | 采用条件 | 工作范围 |
| --- | --- | --- |
| QQ 官方机器人 | 测试账号实际具有普通群消息事件、群内回复、主动群发权限 | 官方鉴权、事件接入、文本发送；只实现可用的一种 Webhook/连接方式 |
| NapCat / OneBot 11 网关 | 官方能力不足时，现成网关在测试群完成所有能力探针 | Java 实现一个 OneBot 11 连接适配器；登录和协议维护由外部网关负责 |

上一版查阅的官方文档出现 `GROUP_MESSAGE_CREATE` 等能力，不代表目标账号已经获权。先实测，若不足，再选择已验证的网关。不能为了沿用官方适配器而将日报缩减为“仅总结 @ 记录”。

OneBot 11 只是协议候选，具体网关版本、事件字段和发送回执在 M0 固定；本计划未安装或验证网关，也不承诺任意版本兼容。

## 3. 最小实现

- 官方路线校验回调挑战/签名、原始 body 和账号；网关路线校验连接 token、账号和允许连接来源，接口不无鉴权暴露。
- 归一化群文本、@ 片段、稳定 ID 和消息时间；不得用展示名称作为群/用户唯一标识。
- 授权群的未 @ 文本照常保存；只有严格命令及 @ 问题触发即时处理。
- 识别自身消息/回声，避免日报发出后再次被当作讨论内容；非文本记录类型即可。
- 发送区分普通回复与主动日报。官方被动消息复用固定来源序列；网关不假设有相同去重保障。
- 重连采用有限退避；记录离线开始/恢复时间。如果网关不能补发历史，保留采集缺口。
- 发送超时无法确认是否已接受时标记 UNKNOWN，不自动重复推送日报。

## 4. 实施清单

- [ ] QQ-01：记录选型和版本，用真实群测试 20 条普通文本，其中至少 15 条未 @。
- [ ] QQ-02：认证、事件转换、去重、群白名单和回声过滤。
- [ ] QQ-03：接入全部 MVP 命令、@ 问答、群级 RAG 引用。
- [ ] QQ-04：验证没有最近用户消息时仍可主动发群日报。
- [ ] QQ-05：断线/恢复、重复投递、发送未知结果和限流提示。

## 5. 验收

AC-QQ-01 要求真实测试群通过：20 条文本准确入库、5 次 @ 问答、所有常用命令、一次主动日报发送，并记录真实接入路线、版本和消息回执。普通文本不自动回复；索引调用不计为聊天生成。

去重、跨群边界和断线缺口复用 AC-GRP-01～03。网关模拟通过只证明 Java 适配器行为，不能代替真实账号验收。
