# 07 MVP 阶段、任务与退出条件

实施更新（2026-11-07）：工程、接口、管理页面与本地自动化验证已落地，逐项进度见 [实施记录](evidence/implementation.md)。下方复选框代表满足完整任务与对应验收，不用代码存在替代真实双平台、真实模型及部署验证。

## 1. 估算与依赖

以一名熟悉 Java 并能开发 React 的开发者为基准，复用现成网关与 UI 组件；不含平台开通、网关采购和不可控等待。新增功能与原平台可靠性任务重新合并估算，并非在旧 25 天上无条件叠加。

| 阶段 | 内容 | 人日 | 前置 | 产物 |
| --- | --- | ---: | --- | --- |
| M0 | pi / 双平台群能力 / embedding 探针 | 3 | 账号与候选网关 | 五项决策、固定版本和能力证据 |
| M1 | Java 单体、数据库、pi、群采集底座 | 4 | D-01、D-04、D-05 | 可运行内核与去重落库 |
| M2 | QQ + 微信群适配与命令 | 4 | M1，D-02/D-03 分别通过 | 群内问答、采集、主动发送 |
| M3 | RAG 持久记忆 | 4 | M1；实测依赖 M2 | 向量索引、群检索和引用 |
| M4 | 每日摘要与持久定时任务 | 4 | M1/M2；复用 M3 的来源规范 | 09:00 昨日分析、去重、运行记录 |
| M5 | React 管理端 | 4 | M1；功能接口随 M2～M4 完成 | 登录与四个功能页 |
| M6 | MVP 联合验收与部署 | 3 | M2～M5 | 验收证据、Compose、恢复手册 |
| 合计 | 最小闭环 | **26** | 另留 5 天缓冲 | 约 6 个工作周，外部等待另计 |

开发时先接 QQ，再复用到微信；M3/M4 可先用固定消息样本推进。M5 可先完成登录与页面框架，不必等所有后端完成。各阶段只做本文列出的 MVP 任务。

## 2. M0：验证可行性

- [ ] T-001：锁定 pi 并由 Java 完成 prompt、结束事件和取消探针。
- [ ] T-002：QQ 未 @ 采集、@ 回复、主动发群及断线行为；选择官方或一个 OneBot 网关。
- [ ] T-003：选定一个微信群网关并执行同样的能力探针；记录登录/费用条件。
- [ ] T-004：固定生成和 embedding 模型，验证中文语义样本、维数和上下文预算。
- [ ] T-005：配置授权群、群管理员、网页管理员、保留期与部署资源。

退出：AC-GATE-01。某平台能力不足时只阻塞该适配器的真实验收，其余模块可继续；不扩展为网关开发项目。

## 3. M1：最小后端与 pi

- [ ] T-101：单 Maven 工程、按包分层、Flyway、pgvector、test/production 配置。
- [ ] T-102：统一群消息、群配置、去重、原文存储、采集缺口记录。
- [ ] T-103：pi RPC、两个运行槽位、即时对话隔离、取消及一个恢复点。
- [ ] T-104：任务结果/Outbox、发送错误分类、重启状态处理。

退出：AC-BASE-01 的后端部分、AC-PI-01～03、AC-GRP-01/03 的模拟部分。前端构建检查在 M5 补齐，不伪称整项已通过。

## 4. M2：群接入与命令

- [ ] T-201：QQ 选定路线的认证、群事件、主动文本发送和回声过滤。
- [ ] T-202：微信选定网关的等价能力、登录失效和重连处理。
- [ ] T-203：help/new/cancel 的确定性逻辑；memory/summary 先接正式应用接口，待 M3/M4 补齐功能。
- [ ] T-204：群白名单、管理员稳定 ID、未知命令及非 @ 不自动回复。

退出：双平台普通文本与问答实测通过；AC-GRP-02 的基础命令部分完成。AC-QQ-01、AC-WX-01 的完整闭环待 M4 后终验，禁止用空的 memory/summary 实现标为通过。

## 5. M3：RAG 持久记忆

- [ ] T-301：按群/时间分块、来源 ID、embedding 批量索引、失败恢复。
- [ ] T-302：pgvector 作用域过滤、Top-K、阈值、来源注入 pi 和引用校验。
- [ ] T-303：接入 @ 问答与 `/memory`；无结果和索引延迟有明确提示。
- [ ] T-304：记忆查询 API、清除/epoch、保留期和删除后旧缓存失效。

退出：AC-RAG-01～04。仅把消息写数据库，或仅恢复 pi 会话，不算 RAG 完成。

## 6. M4：每日分析

- [ ] T-401：每日 HH:mm 配置、Asia/Shanghai、10 秒扫描、重启补跑。
- [ ] T-402：唯一业务日期键，自动/手动触发共用、持久状态和有限重试。
- [ ] T-403：昨日全文快照、按预算分块并由 pi 汇总、覆盖数量与来源记录。
- [ ] T-404：主动发回原群、空群/缺口/超量/迟到处理、Outbox 状态。
- [ ] T-405：`/summary yesterday`、任务配置/执行记录/报告 API。

退出：AC-JOB-01～04；完成 AC-QQ-01、AC-WX-01 的主动日报与全部命令终验。

## 7. M5：React 页面

- [ ] T-501：React + TypeScript + Vite、同源部署、登录/登出、CSRF 与鉴权。
- [ ] T-502：群列表/配置页，展示能力、采集时间、连接状态和管理员 ID。
- [ ] T-503：记忆查询页，显示命中来源和索引状态，确认后清除本群记忆。
- [ ] T-504：任务配置页，启停、时间、手动运行；执行记录页展示报告与发送结果。
- [ ] T-505：表单校验、空/加载/错误状态、分页和关键操作防重复提交。

退出：AC-WEB-01～03，以及 AC-BASE-01 的前后端构建。使用成熟组件，无自定义设计系统、实时大屏或通用管理平台。

## 8. M6：联调与交付

- [ ] T-601：执行 [08](08-acceptance.md)的 24 项必验项，补齐真实双平台证据。
- [ ] T-602：2 小时冒烟、重启、过载边界、失联和一次完整备份恢复。
- [ ] T-603：Compose、配置模板、管理员初始化、接入/运行手册和已知限制。

退出：24 项通过，能力未验证的部分不得写成功。24 小时压力测试、生产 SLA、多副本切换、完整监控告警栈后置。

## 9. 完成定义

每项任务必须有可复现提交/配置、对应验收记录和必要使用说明。报告记录实际版本、场景、结果和证据路径；外部接入受阻标 BLOCKED，其余未执行标 NOT_RUN。计划本身更新不代表任何实现或平台验收完成。
