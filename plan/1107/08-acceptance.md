# 08 MVP 验收清单

## 1. 验收原则

本版以群聊 + RAG + 每日分析 + React 管理闭环为准，共 **24 项必验项**，替代上一版 37 项以私聊/服务号及完整运维为主的清单。已开始实现与本地验证；逐项实际状态见 [实施证据](evidence/implementation.md)，计划修订或模拟测试不代表完整用例通过。

每项记录 PASS / FAIL / BLOCKED / NOT_RUN、代码/依赖版本、操作步骤、实际结果和证据路径。模拟器验证边界；真实 pi 与真实 QQ/微信群验证实际可用性。仅 mock 通过不能宣布双平台 MVP 完成。

## 2. 最小测试环境

- 单实例 Java + PostgreSQL/pgvector：4 vCPU / 8 GiB RAM 起，最多 2 个 pi 进程；网关独立运行或另记其资源消耗。
- 真实环境至少 1 个 QQ 群、1 个微信群，各 2 名测试成员，其中 1 名为配置管理员。隔离测试使用另一个模拟群及账号。
- 使用固定生成/embedding 模型；真实双平台数据在开发过程中跨一个自然日积累，用于一次真实昨日日报，不要求额外跑 24 小时压测。
- 自动化用例可注入 Clock、HTTP 桩和 RPC 进程桩；管理员页面用一个当前 Chromium 桌面浏览器验收。
- 接入计时从 Java 收到完整事件起；模型/网络耗时分开记录。归档入库 p95 目标 ≤1 秒，真实单次问答 120 秒内有结果或明确失败；日报 30 分钟内有终态。

## 8. 最小运行保障

| ID | 操作 | 通过标准 | 证据 |
| --- | --- | --- | --- |

| AC-OPS-02 | 暂停写入并备份数据库/会话；恢复到新目录，核对2群消息、向量、配置和运行；模拟过期数据清理 | 恢复可检索且任务配置有效，旧SENDING不盲重发；清理后超期原文/向量/报告不可访问，活跃数据不误删 | 备份清单、恢复核对、清理记录 |
| AC-OPS-03 | 2小时冒烟，模拟群平均0.2条/秒、每10分钟一次@；中途embedding停机、网关断线、生成队列过载 | 无OOM/无限重试；持久消息可对账；pi≤2、即时队列≤20；索引故障和采集缺口可见；正常采集入库p95≤1秒 | 数量对账、资源/耗时、错误及恢复日志 |

不把24小时压测、专用告警栈、自动扩缩容、生产SLA作为本次MVP门槛。数据隔离、鉴权、去重和真实双平台接入仍是必验项。
