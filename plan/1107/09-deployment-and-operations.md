# 09 MVP 最小部署与运行

## 1. 部署清单

- 一个应用容器：Java、固定 Node/pi、React 静态文件；对外提供管理页和需要的回调入口。
- 一个 PostgreSQL + pgvector 容器，使用持久卷；另挂 pi 会话/恢复点卷。
- M0 选定的 QQ/微信群网关按其运行条件部署，Java 通过受保护网络连接；网关资源和登录要求单列。
- HTTPS 可由已有反向代理提供；管理员 API 必须认证，网关入口必须按所选协议鉴权。

采用单实例，禁止两个应用同时操作同一会话卷。Docker Compose 足够，不增加 Redis、Kafka、独立向量数据库、调度集群或监控平台作为前置依赖。

## 2. 必要配置

| 配置组 | 内容 |
| --- | --- |
| Java/DB/pi | 数据库连接、pi版本与路径、生成模型及凭据、会话卷 |
| 群接入 | QQ选择的路线、微信网关地址/账号、连接凭据；只实现固定协议版本 |
| RAG | embedding模型/版本/维数、批量大小、Top-K、阈值、30天保留期 |
| 定时 | 扫描10秒、时区Asia/Shanghai、默认09:00、日报30分钟与40次生成调用上限 |
| 管理 | 单管理员用户名与密码哈希/初始化密钥、Cookie/CSRF配置 |
| 容量 | pi并发2、即时排队20、每会话排队5、后台摘要并发1、最多5个群 |

部署凭据通过环境或只读挂载提供，`env.example` 留空并解释字段；React 不保存或展示密钥。群开关、管理员ID和每日时间由管理页持久化，不要求每次改配置重新发布。

## 3. 可观察信息够用即可

提供受保护的健康状态、结构化日志及管理页面状态，不要求完整监控栈。

- 连接是否在线、最后收到消息时间、已知采集缺口。
- pi是否可启动、运行中任务、失败原因、发送UNKNOWN。
- 群索引已完成/待处理/失败数和最后更新。
- 日报下次触发时间、状态、来源数量、覆盖范围、报告和发送结果。
- 日志通过traceId/runId定位，默认不输出群正文、thinking或密钥。

普通消息只做持久化和embedding；不逐条调用生成模型。即时问答默认每用户每分钟6次，超额只拒绝问答；日报使用固定总调用/时间上限。MVP记录用量，不建设复杂费用结算或全局预留预算系统。

## 4. 保留与清除

| 数据 | MVP策略 |
| --- | --- |
| 群原文、向量、日报正文和来源 | 默认30天；向量/报告不能继续暴露已清除来源 |
| 临时pi会话/恢复点 | 最后活动7天；清除群记忆时立即使其失效 |
| 任务/发送元数据和去重键 | 30天；不把历史过期消息当成新事件执行 |
| 操作审计 | 90天，仅操作与目标，不含正文 |
| 日志 | 7天 |
| 备份 | 手动或每日停写快照，保留7天 |

清理先逻辑屏蔽，再物理删除文件/行，检查epoch和活跃任务。群记忆删除后旧报告及临时对话也失效；任务审计可保留“报告已清除”。定期保留期清理还需移除引用过期来源的块/报告，关闭该群可能保留旧检索资料的pi临时会话，并在发送前检查来源仍有效；未过期原文和向量保留，不要求整群重建索引。

由于有效原文最多30天，接收时间早于窗口的历史重投不再次触发命令或问答。近期迟到文本可入RAG，已发布日报不自动重跑。

## 5. 停机与恢复

1. 停止接纳生成/定时任务，取消或等待活跃工作；停止网关采集并记录停机缺口。
2. 停止pi文件写入，备份数据库和当前有效会话文件，保存版本与引用摘要。
3. 恢复数据库/文件后校验scope、epoch、任务和向量；启动一个应用实例。
4. 即时RUNNING和日报RUNNING变为INTERRUPTED；未领取的队列可继续，已生成结果只恢复安全的发送。
5. UNKNOWN由管理员核对；调度按当天规则补跑，不补发多天报告。
6. 若使用早于删除操作的备份，重新应用删除审计再开放检索和发送。

MVP要求演练一次完整恢复并记录耗时，不承诺生产RTO/RPO或跨主机高可用。初期升级前备份；不做重叠滚动实例。

## 6. 最短运行手册

交付时包含：构建/启动命令、初始化管理员、连接网关、添加授权群、验证普通文本入库、查询记忆、设置09:00、手动触发昨日、查看缺口/失败、备份恢复、更新固定版本。

对应AC-OPS-01～03。真实群接入不可用时保留明确状态，不能用页面绿色指示灯代替真实收发证据。
