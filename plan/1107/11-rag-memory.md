# 11 MVP：RAG 持久群记忆

## 1. 要解决的问题与边界

用户在群中询问“上周说的发布安排是什么”，即使应用重启或执行过 `/new`，仍能检索本群历史并给出有依据的回答。只持久化 pi 会话，或只建消息表，都不满足这个需求。

首版数据源只有启用采集后的群文本。采用一种 embedding 模型和 PostgreSQL pgvector，不做文件知识库、知识图谱、重排模型、用户画像或跨群检索。

## 2. 索引流程

```text
group_message 提交
  -> 等待索引（不阻塞收件）
  -> 按同一 GroupScope / 时间顺序组成文本块
  -> 固定模型 embedding
  -> memory_chunk + 向量 + 来源引用事务提交
  -> 标记消息索引完成
```

- 单 worker 每 30 秒扫描；每批最多 50 条待索引消息，先按群拆开，禁止一个块含两个群。
- 每块最多 20 条消息或 1,200 Unicode 字符，且不超过 embedding 模型 token 上限；单条过长消息可拆成带偏移的多片段，不静默丢尾部。
- 块内保留消息 ID、发言者稳定 ID/当时显示名、发生时间和原文边界。块是可追溯原文，不先用 LLM 编造事实摘要再建索引。
- `memory_chunk` 保存 `scope`、`memoryEpoch`、`sourceMessageIds`、文本/偏移、时间范围、内容摘要、embedding 模型与版本及向量。
- 相同输入批次以内容摘要和来源集合建立幂等键。消息只有全部片段提交成功后才标为已索引；崩溃可重试，不重复插入块。
- 索引失败保留原文与失败状态，最多自动尝试 3 次，然后在管理页展示“待处理/失败”；重启继续处理待索引项。

默认保留 30 天群文本和向量，超期同步移除。这里的持久化指跨进程/重启可恢复，不承诺无限保留。

## 3. 检索与生成

1. 由已认证的群事件或管理员选择确定 scope，读取当前 memoryEpoch。
2. 只为用户问题生成查询向量；使用与入库相同的模型和维数。问题超过模型支持长度时提示缩短，不隐式换模型。
3. 在 SQL 中强制过滤 scope、epoch、保留期、未删除来源，再计算余弦距离，取 Top-5；MVP 用精确检索，无需 HNSW/IVFFlat 调优。
4. 根据 M0 中文样本确定相似度阈值；不达阈值返回“未找到足够的本群记录”。不能只为了凑 K 条而注入无关记忆。
5. 将命中原文作为带明确边界的“参考资料”注入 pi，最多占 3,000 输入 token；来源编号由 Java 分配。群消息中的指令按资料文本处理，不能改变系统行为、目的群或检索范围。
6. pi 给出回答和来源编号。Java 校验编号属于本次候选集合，输出本群日期、发言者显示信息与来源 ID；不伪造平台不存在的消息深链接。
7. 发送前再次检查 scope/epoch/群启用状态；旧结果失效时不发送。

上下文预算不足时明确减少候选并保留已使用来源；不能只截断 JSON 或切断来源标记。答案格式例如：

```text
发布安排是周五下午完成灰度，负责人是小李。[S1]
来源 [S1]：11-06 14:20，群内消息 m-42。
```

`/memory` 强调基于记录回答；没有证据时不调用模型生成看似记住了的事实。普通 @ 问答也可带本群检索结果；若是在问历史但索引未就绪，应提示范围不足。Java 过滤是权限边界，提示词只是补充。

## 4. embedding 故障与模型版本

- embedding 调用失败不阻止群消息保存，也不影响日报读取原始文本。
- 管理页显示索引完成数、待处理数、失败数和最后更新时间。
- MVP 不支持在线切换 embedding 模型。变更模型/维数必须停索引、执行一次重建并重新验证，禁止混查不同向量空间。
- 依赖不可用时 `/memory` 返回明确的“记忆检索暂不可用”，不能静默当作空记忆；普通问答可提示本次未使用记忆。

## 5. 清除与隔离

网页管理员可确认后清除指定群的已采集记忆；`/new` 不执行清除。

清除事务先提升 memoryEpoch 并使旧消息、块、日报正文不可读；取消旧 epoch 索引/生成/待发送结果，关闭该群 pi 临时会话，再清理对应数据和文件。新接收消息使用新 epoch，继续采集。物理清理可异步完成，但旧内容必须立即从 API、检索和模型输入消失。

保留不含正文的任务/操作审计；恢复旧备份可能恢复其备份时点数据，须按清除审计再次应用删除。首版不实现细粒度单句遗忘或跨用户私有知识空间。

## 6. MVP 验收

| ID | 证明内容 |
| --- | --- |
| AC-RAG-01 | 原文到向量可恢复、重投不重复、重启后仍能检索 |
| AC-RAG-02 | 中文同义问法能命中正确记录，答案给真实来源，无结果不编造 |
| AC-RAG-03 | 不同群/账号绝不互查，群消息中的恶意指令不改变作用域 |
| AC-RAG-04 | embedding 失败可见，清除后旧向量/日报/pi 上下文都不可继续使用 |

统一样本规模和通过阈值见 [08](08-acceptance.md)。无需新增独立向量服务或通用 RAG 平台即可验收此模块。
