# 12 MVP：每日群聊分析与定时任务

## 1. 只有一种任务

实现 `DAILY_SUMMARY`：每个启用群每天一个任务，默认 **Asia/Shanghai 09:00** 分析昨日群文本并发回原群。网页可启停、修改 `HH:mm`、查看运行记录、手动触发昨日任务。

不提供任意 cron、自然语言定时、工作流、外部脚本或跨群聚合。使用 Spring 定时扫描数据库，不需要独立调度服务。

## 2. 时间语义

以 2026-11-07 09:00 触发为例：

```text
businessDate = 2026-11-06
zone = Asia/Shanghai
window = [2026-11-06 00:00:00+08:00, 2026-11-07 00:00:00+08:00)
```

使用 `ZonedDateTime` / `LocalDate` 计算，转换为 UTC 查询；不能用“当前时刻减去 24 小时”替代昨日自然日。以消息发生时间判定归属，接收时间用于识别迟到。

同日 09:00 之前调用 `/summary yesterday`，仍使用同一 businessDate；09:00 到达后不重复生成/发送。配置更新只改变下一次到期时间，不改变既有运行的日期和输入范围。

## 3. 持久化调度与重启

- `daily_schedule` 保存 group、enabled、HH:mm、固定 zone、next_run_at、revision；每 10 秒扫描一次。
- 到期时事务创建 `daily_run` 并推进下一触发时间；唯一键是 `(groupId, taskType, businessDate)`，自动、群命令和网页手动入口共享。
- 多次扫描、重复点击、重启都返回同一逻辑运行；状态 CAS 防止重复领取。
- 重启发现错过触发：只自动补跑**当前本地日期的昨日任务**，且在当天配置时间已到时；更早遗漏记录为未执行，不连发多天日报。
- 将时间从 09:00 改到已经过去的 08:00 时，当天若未运行，则在下一次扫描补一次；已经存在的当日日报不再运行。
- 新启用配置若今日时间已过，同样只创建一次昨日任务；coverage 会体现刚启用采集导致的数据不足。

单实例和数据库唯一键足以覆盖 MVP，不实现分布式锁服务。

## 4. 从全文生成，不能用 RAG Top-K

1. 领取任务时冻结 scope、memoryEpoch、业务日期、输入截止接收时间以及按时间/ID 排序的来源清单，记录消息数和内容摘要。
2. 读取时间窗内**全部已采集有效文本**，排除机器人自身消息、系统通知和命令；记录排除数量、非文本数量和采集缺口。
3. 根据所选模型的输入 token 上限及系统提示词/输出预留分块；默认单块输入不超过 4,000 token。单条超长文本拆成可追溯片段，不漏掉尾部。
4. 每块通过 pi 生成话题、结论、待办、争议/未解决问题和来源 ID。每块都有输入消息清单，不能只取“最相关的几段”。
5. Java 收集分块摘要后由 pi 合并；合并超出预算时再分层压缩。整个日报最多 40 次生成调用、30 分钟运行期限，含排队及分层合并。
6. 校验全部输入片段都已成功处理，保存覆盖统计、来源引用及最终报告；结果与 Outbox 事务提交，再主动发到同一个群。这里保证每段原文都经过分析，摘要本身可以压缩表述，不能承诺逐句复述全部讨论。

支持基线为每群每日 ≤1,000 条有效文本且 ≤100,000 Unicode 字符。超出消息/字符/模型预算时记录 `LIMIT_EXCEEDED`，不生成伪装完整的截断日报；管理员可在页面查看原因。未来再做大群分析扩容。

输入截止后才到达的昨日消息加入 RAG，并在该日报记录“有迟到消息未纳入”；首版不自动重发。重试沿用原冻结清单，避免重试时悄悄换数据范围。

## 5. 结果格式与覆盖说明

报告至少包含：日期/时区、已纳入文本数、排除数、采集覆盖范围/缺口、主要话题、已达成结论、明确提及的待办与负责人、未解决问题、可追溯来源。

- 没有明确负责人与期限时写“未明确”，不让模型补造人物和时间。
- 全日已知在线且无文本：生成固定“昨日无可分析文本”记录，不调用模型；群内默认不发送空日报。
- 有离线/未启用区间：标题写“昨日已采集记录摘要（数据不完整）”，显示缺口，不能宣称代表全群全部发言。
- 无任何采集记录且有缺口：显示“无可分析记录，采集不完整”，不称为群里无人发言。
- 图片/语音/附件未解析，在覆盖说明中明确，不把它们计为已分析内容。

群内最多 3 段，超长正文保存在 React 运行记录页，群内注明截断；即使群展示被截断，也不能截断后台分析输入。

## 6. 运行与发送状态

```text
QUEUED -> RUNNING -> GENERATED -> DELIVERED
              \-> FAILED / INTERRUPTED / LIMIT_EXCEEDED
GENERATED -> DELIVERY_FAILED / DELIVERY_UNKNOWN
QUEUED -> CANCELLED
空数据 -> NO_DATA
```

- 每个逻辑任务只有一个运行 ID 和报告版本；普通重复触发只返回状态或已有报告，不重发。
- 明确 FAILED/INTERRUPTED 的生成可由网页管理员重试一次，沿用逻辑键和输入清单，`attempt` 增加；MVP 不保留复杂分块断点，允许重新分析。
- GENERATED 之后的发送故障只重试明确失败的发送，不重新生成摘要；UNKNOWN 不提供一键自动重发，需要人工核对后记录处置。
- 服务重启将失联 RUNNING 标为 INTERRUPTED，不自动重放模型调用；QUEUED 可重新领取。
- 停用定时配置只阻止未来自动触发；已运行任务允许完成，页面说明该行为。关闭群采集/服务或清除记忆会取消该群未完成任务及待发送结果。
- 日报低优先级，最多占一个 pi 槽位；即时 `/cancel` 不取消日报，群成员不能取消管理员任务。
